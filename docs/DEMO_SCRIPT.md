# 演示与答辩脚本

## 5 分钟演示视频

### 0:00–0:30 痛点与首页

展示安装在手机主屏幕的 BankPilot PWA。强调不用在多层菜单中找功能，首页仍保留资产、快捷操作、最近交易等“正经手机银行”能力。

### 0:30–1:20 绿色：账单分析

输入“分析本月账单”。展示分类金额和异常境外消费。说明这是只读工具，绿色权限自动执行；切到审计台可看到并行的聚合和异常检测节点。

### 1:20–2:20 黄色：小额转账

输入“给张伟转 200 元”。停在操作凭证，指出 Agent 尚未动钱；展示收款人、付款账户、金额、安全级别和操作编号。点击确认，出现账本编号，再回首页验证余额和流水变化。

### 2:20–3:25 红色：强验证

输入“给王芳转 1200 元”。解释日累计超过 1,000 元后策略自动升级。先输入错误 OTP，展示资金未转出；再输入 `123456`，成功后展示凭证。强调授权指纹绑定本次交易，无法移作他用。

### 3:25–4:10 卡与订阅

输入“查看订阅扣费”，展示周期和月均成本；再输入“锁定我的日常卡”，确认后到卡片页看到状态变化。

### 4:10–5:00 审计与架构

打开 `/audit`：选择刚才的任务，展示 DAG、权限裁决、匹配规则、工具节点与不可变事件流。最后用一句话收束：“大模型负责理解，策略引擎决定能不能做，银行核心决定是否真的成功。”

## 10 分钟答辩 PPT

1. **赛题理解（1 分钟）**：问题不是做聊天 UI，而是在少步骤和银行安全之间建立可验证闭环。
2. **产品体验（1 分钟）**：PWA 多端触达、自然语言入口、操作凭证、失败可理解。
3. **场景覆盖（1 分钟）**：余额、账单、转账、订阅、卡管理及扩展路线。
4. **Agent 架构（1.5 分钟）**：意图/槽位 → DAG → Policy → Authorization → Tool → Receipt。
5. **权限分级（1.5 分钟）**：绿色自动、黄色确认、红色强验证；风险只能升级。
6. **银行核心（1 分钟）**：PostgreSQL、状态机、幂等、行锁、双分录、原子事务。
7. **安全机制（1.5 分钟）**：幻觉防护、注入隔离、失败熔断、授权指纹、审计。
8. **真实落地（1 分钟）**：比赛模拟核心如何替换为银行 API/MCP/ESB，明确合规边界。
9. **总结（0.5 分钟）**：从“能聊天”升级为“可授权、可执行、可审计”。

## 作品简介（200 字以内）

BankPilot 是一款“能理解、会规划、受约束”的银行 AI 智能体 PWA。用户只需自然语言即可查询余额、分析账单、识别订阅、管理卡片并完成转账。系统将复杂需求拆解为可审计任务 DAG，以绿色自动、黄色确认、红色强验证实现动态权限控制；通过交易授权指纹、失败熔断、幂等控制、PostgreSQL 原子事务与双分录账本防止越权和虚假成功。产品采用极简移动银行设计，并提供独立安全审计台，完整呈现策略证据、工具调用与账本结果。

## 评委可能追问

**为什么不用真实手机银行 API？** 个人开发者通常拿不到核心交易接口。比赛阶段模拟 Bank Core 是合理的系统边界；真实试点只替换网关适配器，并走银行准入和合规流程。

**大模型被注入后怎么办？** 模型没有写权限，权限规则在独立服务端策略引擎中；所有工具白名单化并重新校验资源归属和参数。

**如何证明没有编造成功？** UI 只有拿到数据库事务提交后的账本编号才显示成功，超时或异常均显示未确认。

**数据库为什么可信？** 金额按分存储、双分录、唯一幂等键、行锁和单事务提交；演示可直接查询每笔 ledger entries 总和为 0。
